Remove the three screen-wide post-processing filters

The whole play area had three filters stacked on it. Together they gave the game a "filtered" look
and were tiring to look at, and the worst of the three was introduced by the pixel-UI pass two
commits ago.

1. `filter: drop-shadow(...)` on the game, battle and map canvases.

   This began as three soft glows - `drop-shadow(0 0 2px)`, `(0 0 10px)`, `(0 0 22px)` - which were
   the softest things on screen, so the pixel-UI pass replaced them with zero-blur offsets to make
   the bloom hard-edged. The result was:

       drop-shadow(1px 0 0 cyan)
       drop-shadow(-1px 0 0 magenta)
       drop-shadow(0 2px 0 blue)

   A cyan copy of every drawn pixel one pixel right, plus a magenta copy one pixel left, is
   CHROMATIC ABERRATION. On hard-edged pixel art it fringes every single edge in red and blue -
   the classic anaglyph-glasses look - and it is genuinely dizzying to look at, which is exactly
   what was reported. `contrast(106%) brightness(104%) saturate(112%)` was stacked on top of it.
   The whole rule is gone; the canvas is now shown as drawn.

   Worth stating plainly: "hard-edged instead of blurred" was the right instinct and the wrong
   execution. A zero-blur shadow with an OFFSET is not a hard glow, it is a colour fringe. The
   hard-edged glow this project actually wanted is `pixelGlow`, which is made of stepped rings
   drawn inside the scene - not a filter over the whole canvas.

2. The `.scanlines` overlay: a 4px hard black stripe over the entire screen at 30% opacity, a CRT
   filter. Its settings checkbox had already been dropped from the markup, so nothing could turn it
   off, and its toggle listener in main.ts was dead code reading `getElementById('scanlineOverlay')`
   behind an optional chain that never fired. Element, CSS and listener all removed.

3. The `.bloom-ambient-lens` overlays: two radial gradients with `mix-blend-mode: screen` tinting
   the whole view cyan and purple. Both removed.

`image-rendering: pixelated` is deliberately kept. It is not a filter: it stops the browser from
smoothing the canvas when it is scaled, which is the opposite of one, and removing it would blur
the pixel art.

`npm run check:css` now fails the build if any of the three reappears in the built markup, matched
on the CSS property rather than the bare word so the stylesheet's own comment explaining the
removal does not trip it. The `z-35` Tailwind spot check is retired with the overlay, since that
element was its only user and Tailwind therefore no longer emits it.

One process note, because it cost a cycle: the removal script found nothing on its first run
because index.html uses CRLF and the literal match was written with LF newlines. It failed
silently - `includes` returned false and the file was written unchanged. The reworked script
normalises to LF for matching and writes CRLF back, which also keeps the diff to the lines that
actually changed.

Verification: 133 tests green, typecheck green, 10/10 Tailwind spot checks, 12/12 pixel UI
components present, 8/8 glass utilities absent, 5/5 screen-filter tokens absent.
